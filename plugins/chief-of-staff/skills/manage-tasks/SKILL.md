# Manage Tasks

Use the task system configured by the current project or supplied context root. Fetch its current schema before writing. Do not create a second task system.

## Operating model

- Capture quickly with only known fields.
- Keep personal commitments separate from shared project delivery records.
- Link a personal next action to its canonical project page when confidently known.
- Completing a personal task does not complete the linked project unless the user asks.
- Prefer status changes over deletion.
- Treat an intended work date differently from a consequential deadline.

## Planning

Plan from active tasks, linked project records, current priorities, and real calendar constraints. Recommend no more than three meaningful weekly outcomes and leave realistic space.

Applying an approved plan means updating the configured task system. Create calendar blocks only when explicitly requested. At review time, complete, deliberately reschedule, or abandon unfinished work rather than rolling everything forward silently.

When the context does not identify a task system or required fields, ask for that configuration instead of inventing one.

## Learning loop

When repeated friction suggests a schema or workflow change, propose one small improvement. Do not add fields, statuses, databases, or integrations without approval.
